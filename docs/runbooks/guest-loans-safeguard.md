# Runbook — запобіжник гостьових позик (Етап 10, кроки 10f.1–10f.2)

Джерело: [execution plan Етапу 10, §7.3](../plan/stage-10-real-world-history.md#73-технічний-запобіжник-до-зняття-t9).

> **D2 — відкритий release blocker.** Запобіжник його **не знімає** і **не гарантує**, що введені дані
> синтетичні: код не відрізняє реальну людину від синтетичної. **Реальні персональні дані гостя
> (ім'я, аліас, email, контакти) заборонені в усіх середовищах** — development, test, staging і
> production. Цю заборону тримає Product Owner організаційно.

## Конфігурація

| Змінна                       | За замовчуванням | Значення                                  |
| ---------------------------- | ---------------- | ----------------------------------------- |
| `GUEST_LOANS_ENABLED`        | `false`          | рівно `true` або `false`                  |
| `GUEST_LOANS_SYNTHETIC_ONLY` | `false`          | рівно `true` або `false`                  |

Перевірка — `apps/api/src/config/env.validation.ts`, fail-fast на старті. Значення `1`, `0`, `yes`,
`TRUE`, порожній рядок, пробіли — помилка (`Некоректне оточення`).

| Середовище                  | `ENABLED` | `SYNTHETIC_ONLY`      | Результат                            |
| --------------------------- | --------- | --------------------- | ------------------------------------ |
| будь-яке                    | не задано / `false` | будь-яке    | функція вимкнена                     |
| `production`                | `true`    | будь-яке              | **API не стартує**                   |
| не-`production`             | `true`    | не задано / `false`   | **API не стартує**                   |
| не-`production`             | `true`    | `true`                | функція увімкнена (лише тестові дані) |

`production` — це `NODE_ENV=production`. Середовища beta (Етап 11) теж мають `NODE_ENV=production`.

## Що робить API при вимкненій функції

`GuestLoansEnabledGuard` (`apps/api/src/common/guest-loans-enabled.guard.ts`) відповідає
`403` із `code: FEATURE_DISABLED` до виконання сесійного guard'а, handler'а, сервісів і запитів до БД.
Guard має стояти **першим** у `@UseGuards(...)`. Чинні позики між зареєстрованими користувачами запобіжник не зачіпає.

### Маршрути під запобіжником (10f.2)

`POST`, `GET` і `PATCH /api/v1/me/external-borrowers[/:id]` — приватні контакти власника. При вимкненій функції всі три
відповідають `403 FEATURE_DISABLED` навіть без сесії і навіть з невалідним тілом; жодного запиту до БД не робиться.
Гостьових позик (`POST /loans/guest`) і `DELETE` контакту ще немає.

### Доступність для UI

`GET /auth/session` (а також `register`, `login`, підтвердження email) повертає `features.guestLoans` — значення `GUEST_LOANS_ENABLED`
з конфігурації сервера. Web не має власного прапора: при `false` або відсутньому значенні сторінка `/contacts` і посилання «Контакти» не
показуються, контактні API не викликаються. При `true` UI показує банер «Лише синтетичні тестові дані».

### Що це не вирішує

- Контакт зберігає лише alias. Прапорець «Я повідомив(-ла) людину» (`ownerInformed`) — заява власника, а не підтвердження самої людини й не
  правова підстава; юридичне повідомлення не реалізоване (D2).
- **Q2 відкрите:** строк зберігання контакту без позик не погоджено. `retainUntil` у 10f.2 не встановлюється, не читається й не очищується;
  наявне nullable-поле не означає погодженого безстрокового зберігання. Retention (10h) не реалізовано, тому контакти жодним процесом
  не видаляються — ще одна причина використовувати лише синтетичні дані.
- Alias не потрапляє в аналітику, сповіщення, публічні відповіді та логи; його віддають лише маршрути `/me/external-borrowers`.

## Зняття запобіжника

Лише після виконання **всіх** критеріїв §7.2 плану й письмового рішення PO, окремою зміною коду
(`GUEST_LOANS_PRODUCTION_ALLOWED`). Зміною змінних оточення запобіжник не знімається.
