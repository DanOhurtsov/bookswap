# BS-143 — особиста історія як третя вкладка «Позичань»

Статус: реалізовано на гілці `codex/bs-143-loans-history-tab`, очікує незалежного рев'ю.

## Постановка

Окремий розділ «Історія» (`/history`) у навігації «Моєї бібліотеки» прибирається. Особиста історія
стає третьою внутрішньою вкладкою розділу «Позичання». API, БД, міграції, модель історії та правила
приватності не змінюються.

## Погоджені рішення

1. Третя вкладка — `/loans?tab=history`.
2. `/history` перенаправляє на `/loans?tab=history`.
3. Обидві підвкладки історії («Що я брав», «Що в мене брали») зберігаються.
4. Чинні адреси з `role` і `loanId` працюють як раніше.

## A. Навігація

- `LIBRARY_SECTIONS`: «Книжки» (`/library`) → «Позичання» (`/loans`) → «Вішлист» (`/wishlist`).
- Усередині «Позичань»: «Мої книжки» → «Я позичаю» → «Історія».
- На вкладці історії поточним розділом лишається «Позичання» (`aria-current="page"` + підкреслення),
  у хедері — «Моя бібліотека». Шлях той самий (`/loans`), тож `currentLibrarySection` і хедер не
  змінювалися.
- Рамка одна: `LibrarySectionPage` (єдиний `main`, `h1` «Моя бібліотека», навігація, `h2` розділу)
  рендерить лише екран `/loans`; вміст історії вкладено в панель вкладки без власної рамки.
- Посилання «Гостьові позики» стоїть над вкладками на всіх трьох вкладках (як і раніше — над
  вкладками списку).

## B. Стан в адресі

Розбір і побудова параметрів — у чистій моделі `features/loans/model/loans-address.ts`:

| Адреса | Що відкривається |
| --- | --- |
| `?loanId=…` (з будь-якими іншими параметрами, зокрема `tab=history`) | Одне позичання — пріоритет над вкладками |
| `?tab=history` | «Історія» → «Що я брав» |
| `?tab=history&historyView=lent` | «Історія» → «Що в мене брали» |
| `?tab=history&historyView=<інше>` | «Історія» → «Що я брав» |
| `?role=borrower` | «Я позичаю» |
| без `tab=history`, `role` відсутній чи невідомий (зокрема `tab=<інше>`) | «Мої книжки» |

- Вибір «Історії» ставить `tab=history`; вибір «Мої книжки» / «Я позичаю» прибирає `tab` і ставить
  відповідний `role`. Вибір підвкладки ставить `tab=history` і `historyView`.
- Усі решта параметрів зберігаються (`status`, сторонні, а також `role`/`historyView` іншого рівня:
  повернення на вкладку відновлює попередню підвкладку).
- Перемикання — `router.replace`, як і раніше: вкладка — фільтр, а не крок навігації.
- URL — єдине джерело стану: пряме відкриття, перезавантаження й зміна адреси на тому самому маршруті
  показують відповідну вкладку.
- «Показати всі» в одному позичанні веде на `role` із завантаженого позичання; адресу будує та сама
  модель (`/loans?role=owner|borrower` — без змін).

## C. Вміст історії

- Перенесено без змін поведінки: `useMyHistory()` і `GET /me/history`, картки (назва → `/works/:id`,
  автори, видання, рядок історії з датами й іменами за правами, «Уся історія примірника» →
  `/copies/:id/history`), ключ гостьового запису без `loanId`.
- Гостьові записи лишаються анонімними: компоненти не знають про `contact`/`alias`, жодних нових полів.
- Loading / error / порожні стани обох підвкладок — ті самі тексти («Ви поки нічого не брали.»,
  «У вас поки нічого не брали.»).
- Режими — окремі компоненти: `LoanListPanel` (`useLoans`) і `LoansHistoryPanel` (`useMyHistory`)
  монтуються лише на своїй вкладці, `SingleLoanView` (`useLoan`) — лише з `loanId`. Історія не читає
  список поточних позичань, а списки — історію. Одна відповідь `GET /me/history` обслуговує обидві
  підвкладки, тож їх перемикання нового запиту не надсилає.
- Legacy-хуки (`useApiResource`, `useLoans`, `useLoan`, `useMyHistory`) не мігровано.

## D. Старий маршрут

- `app/(pages)/history/page.tsx` — Server Component із `redirect('/loans?tab=history')` (константа
  `LOANS_HISTORY_HREF` з `features/loans`). Для прямого запиту — HTTP 307 без HTML старого екрана.
- Старі query-параметри `/history` не переносяться: вони ніколи не визначали стан того екрана.
- Гість: `/history` → `/loans?tab=history` → звичайний захист `/loans` → `/login`.
- Внутрішніх посилань на `/history`, крім навігації розділу, не було. `/copies/[id]/history`,
  `/works/[id]/history` і відповідні API не змінювалися.

## E. Архітектура

- `app/(pages)/loans/page.tsx` — тонкий серверний route wrapper (`<LoansScreen />`), без
  `'use client'`.
- Нова фіча `features/loans` (зареєстрована в `KNOWN_FEATURES`):
  - `model/loans-address.ts` — адреса розділу; `model/use-loan-actions.ts` — перенесений хук дій;
  - `components/LoansScreen.tsx` — захист сесії, Suspense, розвилка режимів, зовнішні вкладки;
  - `LoanListPanel`, `SingleLoanView`, `LoansHistoryPanel`, `LoanCard`, `LoanCardActions`
    (`LoanActions`, `ApproveForm`, `LoanDialog`) — перенесено з route-файлів без зміни логіки дій;
    коментарі перекладено англійською разом із перенесеним кодом.
  - Публічна поверхня: `index.client.ts` (`LoansScreen`), `index.ts` (`LOANS_HISTORY_HREF`).
- Доступність: наявні компоненти вкладок (Base UI `Tabs`, варіант `line`). Назви tablist різні:
  зовнішній — «Вкладки позичань» (раніше «Бік позичання»: з третьою вкладкою це вже не бік),
  вкладений — «Вигляд історії». Активна вкладка — `aria-selected="true"` і підкреслення.

## Критерії готовності та перевірки

| Вимога | Доказ |
| --- | --- |
| Порядок розділів і вкладок | `library-sections.spec.ts`, `LibrarySectionPage.spec.tsx`, `LoansScreen.spec.tsx`, браузер |
| URL / fallback / пріоритет `loanId` / збереження параметрів | `loans-address.spec.ts`, `LoansScreen.spec.tsx` |
| Reload і пряме відкриття | `LoansScreen.history.spec.tsx` (свіжий рендер з адресою), браузер (`reload`, нові вкладки) |
| Редирект `/history` | `app/(pages)/history/page.spec.tsx`, браузер (307, авторизований, гість) |
| Обидві підвкладки, loading / error / empty | `LoansScreen.history.spec.tsx` |
| Регресії `role`, `loanId`, «Показати всі», дій, входу до гостьових позик | `LoansScreen.spec.tsx`, браузер |
| Приватність alias | `alias-privacy.spec.ts` перевіряє всі файли `features/loans` (не лише route wrappers) і що перенесені екрани в переліку; браузер — alias відсутній у розмітці |
| Тонкі route wrappers | `app/(pages)/loans/page.spec.tsx`, `app/(pages)/history/page.spec.tsx` |
| Клавіатура, фокус, мобільна ширина, теми | `LoansScreen.history.spec.tsx` (Tab/стрілки/Enter), браузер: 375 px, світла й темна |

Браузерний сценарій — `apps/api/test/browser/loans-history-tab.browser-spec.ts` (реальні `next dev`,
API і тестова БД; нічого не підставлено):

1. Хедер → «Моя бібліотека» → «Позичання» → «Історія» → «Що я брав» → «Що в мене брали» → reload →
   «Я позичаю»: адреси, вибрані вкладки, один `h1`/`main`, `aria-current`, імена сторін, посилання на
   твір і історію примірника, анонімний гостьовий запис без alias у розмітці, лише `GET /me/history`
   на вкладці історії, клієнтська навігація без перезавантаження.
2. Пряме відкриття `/loans?tab=history&historyView=lent`, `/loans?tab=history` і
   `/loans?loanId=…&tab=history` (одне позичання, «Показати всі» → `/loans?role=owner`).
3. `/history?…` — 307 на `/loans?tab=history` без параметрів і без старого екрана; авторизований
   користувач; гість → `/login`.
4. 375 px у світлій і темній темах: клавіатурою (Tab, стрілки, Enter) до «Історії» й «Що в мене
   брали», видимий фокус, без горизонтального скролу, вкладки в межах екрана, активні вкладки мають
   `aria-selected` і видиме підкреслення, неактивні — ні.

Середовище браузера: у WSL бракує `libasound.so.2` — взято з пакета `libasound2t64` (`apt-get
download`, розпаковано в тимчасову теку, `LD_LIBRARY_PATH`), як у BS-133. Повний `goto` зі щойно
завантаженої сторінки в цьому середовищі валить рендерер headless Chromium («Page crashed») на будь-
якому маршруті — контрольний прогін `/library` → `/wishlist`, яких задача не змінює, падав так само.
Тому прямі відкриття в сценарії 2 робляться в нових вкладках із cookie сесії; таймаути й перевірки не
змінювалися.

## Перевірка

- Baseline до змін: специфікації `/loans`, `/history`, розділів бібліотеки, NavBar, alias-privacy —
  10 наборів, 95 тестів, зелені.
- Web: `features/loans/**` — 3 набори, 56 тестів; увесь web — 152 набори, 1923 тести.
- Браузер: `loans-history-tab` — 5 з 5, три запуски поспіль.
- `pnpm lint`, `pnpm typecheck` — чисто.
- `./gate.sh` — exit 0 (другий запуск): shared 645, api 2108, web 1923, `test:db` 1499 + 260. Перший
  запуск — exit 1: `AddBookScreen.spec.tsx`, один тест перевищив таймаут 5 с, коли тести web ішли
  паралельно з build (той самий збій описано в BS-145). Цей файл задача не змінює; окремо він проходить
  (155 з 155). Там само виправлено act-попередження в новому `LoansScreen.history.spec.tsx`.
